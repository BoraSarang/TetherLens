## 핫스팟 지연시간(Ping)상태별 알림 메시지 제안 (핫스팟의 경우에만 알림 발생)

알림을 보낼 때 가장 중요한 것은 "사용자가 피로감을 느끼지 않는 시점"에 "상태 파악과 해결책이 한눈에 보이는 메시지"를 제공하는 것입니다.

매초 수행되는 Ping 측정마다 즉시 알림을 띄우면 폭탄처럼 알림이 쌓여 사용자가 앱을 삭제하게 되므로, 트리거 조건(시점)과 메시지 구조를 명확히 정의해 두어야 합니다.

1. 알림을 보여줘야 하는 시점 (트리거 조건)
단순한 1~2회의 일시적 핑 튐(Spike)은 무시하고, 지속성과 상태 변화를 기준으로 발송.

① 상태 악화 시점 (정상 → 비정상/위험)
 조건: 설정한 기준값(예: 8.8.8.8 Ping 250ms 이상)이 최근 5회 연속 또는 10초 이상 유지될 때
 이유: 순간적인 시그널 흔들림으로 인한 오알람 방지

② 서비스 영향성 발생 시점 (패킷 손실 감지)
 조건: 지연 시간과 상관없이 패킷 손실률(Packet Loss)이 10% 이상 지속될 때
 이유: RTT 숫자 자체는 낮아도 패킷이 끊기면 실제 사용자 경험(동영상 멈춤, 웹페이지 안 열림)은 급격히 악화됨

③ 네트워크 병목 전환 시점
 조건: 인터넷 망은 문제없다가 게이트웨이(로컬 핫스팟) 쪽 핑이 갑자기 폭증(> 100ms)할 때
 이유: 사용자가 스마트폰과 멀어졌거나 주변 Wi-Fi 간섭이 시작된 즉각적인 신호이므로 바로 알려주는 것이 유용함

필수 참고: 오알람 및 도배 방지 규칙 (필수)
 쿨다운(Cooldown) 타임 설정: 한 번 알림이 나간 후 최소 1~3분 동안은 동일 등급 알림 재발송 금지
 상태 복구 알림: 위험/비정상 상태에서 다시 정상 범위로 진입하여 10초 이상 유지될 때 1회 복구 알림 발송 (사용자에게 안도감 제공)

2. 상태별 알림 메시지 제안
사용자는 Ping 280ms 같은 전문 용어보다 "지금 내 인터넷으로 뭘 할 수 있고, 어떻게 해결해야 하는지"를 알고 싶어 합니다.

헤드라인: 현재 상태 요약 (명확한 경고)
본문: 원인 추정 및 사용 가능한 작업 안내
액션버튼/팁: 사용자가 취할 수 있는 즉각적인 행동

[비정상 / Warning] 핫스팟 지연 증가 (100~250ms)
헤드라인: 🟡 핫스팟 반응 속도가 느려졌습니다
본문: 데이터 속도 제한(QoS) 또는 신호 약화가 의심됩니다. 고화질 영상이나 실시간 게임 시 끊김이 발생할 수 있습니다.
💡팁: 핫스팟 스마트폰을 창가 쪽으로 옮겨보세요.

[위험 / Critical - Case 1] 외부 인터넷/QoS 문제 (8.8.8.8 > 250ms)
헤드라인: 🔴 인터넷 연결 상태 매우 위험
본문: 데이터 QoS(속도 제한) 구역이거나 셀룰러 신호가 매우 약합니다. 메신저/텍스트 외의 서비스 이용이 어렵습니다.
💡 팁: 통신사 데이터 잔여량을 확인하거나 핫스팟을 재연결해 보세요.

[위험 / Critical - Case 2] 로컬 핫스팟 연결 문제 (게이트웨이 > 80ms)
헤드라인: 🔴 핫스팟 기기와의 연결이 불안정합니다
내용: 스마트폰과의 거리가 멀거나 주변 Wi-Fi 간섭이 심합니다.
💡 팁: 스마트폰 가까이 이동하거나, 핫스팟 설정을 5GHz 대역으로 변경해 보세요.

[복구 / Recovery] 네트워크 정상화
헤드라인: 🟢 인터넷 연결이 다시 원활해졌습니다
내용: 지연 시간이 정상 범위(100ms 이하)로 회복되었습니다. 모든 서비스를 정상적으로 이용하실 수 있습니다.
